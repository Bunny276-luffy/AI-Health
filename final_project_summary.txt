1. EXECUTIVE SUMMARY
--------------------
NeuroScan is a production-grade, full-stack, cross-platform medical AI imaging
system. The system goes beyond standard detection by quantifying its own prediction
uncertainty via Monte Carlo Dropout, providing statistically guaranteed conformal
prediction intervals, grounding an LLM assistant strictly in numeric scan data,
and supporting federated training across hospital nodes without sharing raw data.

It progressed through 3 major engineering phases:
  Phase 1: Mock architecture & full-stack integration
  Phase 2: Real PyTorch/ONNX deep learning pipeline
  Phase 3: 6-feature advanced AI extension (LLM, Radiomics, FL, Conformal, etc.)


2. COMPLETE TECHNOLOGY STACK
-----------------------------
Frontend (Client Layer)
  - Core:          Next.js 14, React.js, TypeScript (strict mode, no `any`)
  - Styling:       Tailwind CSS (Dark medical theme, Glassmorphism)
  - Visualization: HTML5 Canvas (heatmaps, bounding boxes, side-by-side diffs)
  - Icons:         Lucide React
  - HTTP:          Axios (multipart uploads), native fetch() (SSE streaming)
  - Deployment:    vercel.json + NEXT_PUBLIC_API_URL environment variable

Backend (AI & Data Layer)
  - API Core:          Python 3.10+, FastAPI, Uvicorn
  - Edge Inference:    ONNXRuntime (CPU/GPU-agnostic model execution)
  - Deep Learning:     PyTorch, MateuszBuda U-Net architecture
  - Image Processing:  OpenCV, SimpleITK (affine registration)
  - Medical Imaging:   pydicom (DICOM metadata extraction)
  - Report Generation: ReportLab (dynamic PDF synthesis)
  - LLM Integration:   Anthropic Claude claude-sonnet-4-20250514 (grounded VQA)
  - Federated Learning: Flower (flwr), Fernet symmetric encryption, Gaussian DP
  - Containerization:  Docker, Docker Compose
  - Deployment Target: Render / Railway / Fly.io (containerized)


3. COMPLETE SYSTEM LAYERS & FEATURES
--------------------------------------

--- CORE PIPELINE (Phases 1-2) ---

Layer A: Frontend Dashboard
  - Drag-and-drop upload panel: JPG, PNG, .dcm support
  - HTML5 Canvas visualization: real-time heatmap overlay + bounding boxes
  - Organ-aware dynamic title: "NeuroScan — Brain/Lung/Liver/Prostate Detection"
  - Clinical alarm banners triggered when Epistemic Uncertainty > 30%
  - Responsive 3-column grid layout (upload / visualization / uncertainty)

Layer B: Image Preprocessing Engine
  - Multi-part form binary ingestion via FastAPI
  - OpenCV decoding → organ-specific resize (Brain: 256x256, Lung: 512x512, etc.)
  - ImageNet standardisation: mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]

Layer C: Monte Carlo Dropout Inference Core
  - MateuszBuda U-Net exported to `unet.onnx` via local repo cloning
  - 10-pass MC Dropout ensemble per uploaded scan:
      • Aleatoric branch: Gaussian input noise per pass (sigma=0.05) [TTA]
      • Epistemic branch: stochastic 10% activation dropout mask per pass
  - Stacked probability maps → mean_prob_map + variance_map
  - Outputs: tumor_probability, bounding_boxes, uncertainty heatmap

Layer D: Uncertainty Quantification
  - Epistemic Uncertainty: 70% of total variance (model knowledge gap)
  - Aleatoric Uncertainty: 30% of total variance (data/image noise)
  - Both exposed as 0-100% frontend metrics
  - `is_high_uncertainty` flag at 25% total threshold

Layer E: Self-Calibrating Diagnostic Loop (SimpleITK)
  - Triggered automatically if Epistemic > 30%
  - Executes SimpleITK Affine/Euler2D image registration against baseline
  - Re-runs ONNX inference with calibration_factor = 1.15 applied
  - Transformation type logged to API response + PDF report

Layer F: DICOM Metadata Extractor (pydicom)
  - Intercepts .dcm binary streams natively via pydicom
  - Extracts: PatientAge, Modality, SliceThickness
  - Falls back gracefully for standard JPG/PNG uploads
  - Metadata injected into API response + embedded in PDF output

Layer G: Diagnostic PDF Report (ReportLab)
  - Sections: Inference Results, Uncertainty Estimation, DICOM Metadata,
              Radiomics Analysis, System Metrics, Calibration Status
  - Color-coded findings (red = tumor detected, green = clear)
  - Clinical disclaimer footer on every generated report
  - Streamed directly to browser as downloadable binary

Layer H: Custom PyTorch Training Pipeline
  - MedicalSegmentationDataset: loads image/mask pairs from local folders
  - Data augmentation: random horizontal + vertical flips
  - DiceBCELoss: combined Dice + Binary Cross Entropy (handles class imbalance)
  - Adam optimizer, hardware-agnostic (CUDA → MPS → CPU auto-detection)
  - Post-training automatic ONNX re-export overwrites production `unet.onnx`
  - verify_training.py: synthetic dummy dataset test to validate the math

--- ADVANCED FEATURE SET (Phase 3 — 6 New Features) ---

Feature 1: Visual Question Answering (VQA) — /api/v1/vqa
  - POST /api/v1/vqa/stream: Server-Sent Events token-by-token LLM streaming
  - POST /api/v1/vqa: synchronous fallback for PDFs/pipelines
  - Claude claude-sonnet-4-20250514 grounded strictly to numeric scan_context
  - System prompt encodes all metric values to prevent hallucination
  - Frontend: text input, suggested question chips, streaming blinking cursor
  - Yellow "AI-generated — not a clinical diagnosis" disclaimer banner
  - Env var: ANTHROPIC_API_KEY

Feature 2: Radiomics Analysis — radiomics_service.extract_features()
  - Executes after every ONNX inference pass on the tumor ROI
  - First-Order Statistics: Energy, Entropy, Variance, Kurtosis
  - GLCM Texture: Contrast, Correlation, Homogeneity, ClusterShade
  - Pure NumPy/OpenCV — no heavy C++ pyradiomics dependency required
  - Normal ranges per feature: Green (normal) / Amber (borderline) / Red (abnormal)
  - Frontend: 8-card responsive grid, status badges, clinical descriptor text
  - PDF: "Radiomics Analysis" section added to every report

Feature 3: Temporal Scan Comparison — /api/v1/compare
  - Accepts 2 scan uploads + optional ISO date strings
  - Runs full independent MC Dropout inference on both scans
  - Computes: probability_delta, volume_delta_percent, uncertainty_delta
  - Volume Doubling Time (VDT) via Schwartz formula: T·ln(2)/ln(Vb/Va)
  - VDT clinical interpretation: Fast (<100d) / Moderate / Slow / Indolent
  - Severity label: stable / moderate / critical
  - Frontend: dual upload + date pickers, side-by-side heatmap Canvas,
              delta arrows (↑/↓), colour-coded severity, VDT string

Feature 4: Multi-Organ Model Routing — organ_registry.py
  - OrganType enum: BRAIN | LUNG | LIVER | PROSTATE
  - Organ-specific ONNX sessions loaded lazily, cached in memory
  - Organ-specific resolutions: Brain=256x256, Lung=512x512, Liver=256x256,
    Prostate=320x320
  - Fallback to brain unet.onnx when organ model file not yet present
  - /api/v1/analyze extended with `organ: str = Form("BRAIN")`
  - Frontend: 4-button styled selector (Brain/Lung/Liver/Prostate) with icons
  - Dashboard title updates dynamically to reflect selected organ

Feature 5: Federated Learning Architecture — fl_server.py / fl_client.py
  - Server: Flower (flwr) FedAvg aggregation strategy
  - Differential Privacy: Gaussian noise (ε=1.0, δ=1e-5) injected post-aggregation
  - σ = sqrt(2·ln(1.25/δ)) · sensitivity / epsilon
  - Post-aggregation: weights auto-exported to unet.onnx
  - Client: hospital node trains 3 local epochs per federation round
  - Fernet (AES-128-CBC + HMAC-SHA256) symmetric key encryption of weight deltas
  - Docker Compose: 1 server + 3 simulated hospital client containers
  - No raw patient data leaves hospital nodes — privacy-preserving by design

Feature 6: Conformal Prediction Layer — conformal.py
  - Split conformal prediction (distribution-free, model-agnostic)
  - Calibration: nonconformity scores s_i = 1 - p_i on held-out set
  - q_hat = ceil((n+1)(1-α))/n quantile of calibration scores
  - Coverage: 90% statistical guarantee (α=0.10)
  - Per-prediction output: lower_bound, upper_bound, prediction_set
  - Calibration state persisted to conformal_calibration.json
  - Frontend: replaces raw "System Confidence" with [lower, upper] display
  - Interactive tooltip explaining conformal prediction in plain English
  - Interval width classification: Tight / Moderate / Wide
